# 时间驱动的 Plan and Execute

```bash
python main.py resume.pdf --duration-minutes 30 --job-title "AI Engineer"
```

CLI 与 `/ws/agent/` 都启用这条路径。WebSocket `start` 接受 `duration_minutes`
（默认 30，正整数），浏览器 `/agent/` 有对应时长输入。

## 职责与约束

- `InterviewPlannerAgent` 生成有序话题列表，每项包含已有 project/topic ID、陈述式考察目标、
  完成条件、时间预算和预计题数。项目汇总从话题计算，避免重复维护不一致的数字。
- Planner 的严格输出 schema 没有 question/text 字段，不接受额外字段，目标拒绝问号。
  提示词禁止生成具体问题；具体问题、澄清和追问由现有 Question Agent 生成并接受质量检查。
- `expected_questions` 是包含主问题和追问的预计题数，可以提前结束，也可以由重规划增加。
- `max_questions` / `max_questions_per_project` / `max_questions_per_topic` 是安全上限，
  默认 40 / 20 / 8，Planner 不能扩大它们；达到上限后结束或切换，不再折算成时长。
- Executor 可继续当前有效话题，或提前切换到下一个计划中的可用话题；不能自行打开计划外话题。

## 计时

解析简历、初始规划和首题生成属于准备，不计入面试时长。首题准备完成时记录服务端
`clock_started_at`；之后每轮从该持久化时刻重新计算累计实际时间，包含阅读、作答、评价、
重规划和问题生成。重复 feedback 返回已有动作，不重复计算或提交状态。
进程重建后仍沿用原开始时间；当前没有暂停语义。报告生成不计入面试时间。

收到回答和生成问题前后检查时间；剩余时间不足以保留收尾及最低一轮时间时停止提问。
生成过程中时间耗尽的题目不发布。正在输入的回答允许提交，因此目标时长不是强制切断时间。
收尾预算是停止追加技术问题的余量，本版本直接进入结果展示，不额外生成收尾题目。

## 调整与故障处理

话题完成、明确不会、连续无新信息、预计题数/时间分配用尽、回答矛盾或计划超过剩余时间时，
检查是否需要重规划。默认冷却为两道已回答问题；计划已无可执行项且仍有可用话题时可立即调整。
已完成和已跳过的话题不能重新打开；完成前的重要细节可以增加追问。
只向 Planner 提供回答分析，不提供评分维度分数来引导出题。

校验器检查 ID、重复话题、时间总和、最低话题时间、三层安全上限。
重规划的输出表示“从现在开始的剩余分配”；保存时加上实际已用时间和题数，形成累计目标。
调用 Planner 自身耗时先从机动预算扣除，再压缩后续话题。历史版本保留原快照。

初始规划失败使用确定性分配；重规划超时或无效保留旧计划，时间和安全上限继续生效。
如果旧计划不再有可执行项，可以提前结束，不为填满时长重复提问。
初始计划随初始化保存；后续计划、进度和下一动作在同一个版本检查与原子提交中保存。

## 配置、输出和兼容

`agent.planning` 可配置 `timeout_seconds`（20）、`replan_cooldown_questions`（2）、
`minimum_question_seconds`（30）。JSON 结果包含 `interview_plan`、`plan_history`、
`topic_progress`；Markdown 执行记录展示计划修订与实际执行时间、题数和关闭原因。
预算是每个版本的累计目标，关闭话题保留其最后目标用于比较；计算可执行预算时只统计
未关闭话题的剩余分配，不能把历史/关闭话题的预算再次加到剩余时间上。

共享请求保留 `planning_enabled=False` 兼容已有直接调用方；这些调用方仍可显式传入
`elapsed_seconds`。CLI 和网页默认开启，不再使用固定每题 120 秒。
第一版时间规划只支持 `project_deep_dive` 阶段，最短 60 秒。
