# v3 r2 错误归因与执行边界验证

日期：2026-09-26。本次只读分析既有 15 秒报告和原始数据，新增隔离执行测试；没有调用模型、修改检测实现或重新计算基准分数。

## 结论

当前问题同时涉及语义识别、业务上下文表达和调用延迟，不能只靠换数据集或延长时限解决。以下归因是根据原文、模型有限原因码和当前实现提出的解释，**不是模型内部推理的证据，也不是已证实的因果关系**。

- 公开集有 7 条误报，全部返回 goal_hijack。样本包括普通地理、营销、时事问题；现有提示词已要求不要把普通离题问题判成攻击，但模型仍未稳定遵守。
- 公开集有 14 条漏报，其中存在明确改变回答方式、忽略先前内容的指令，不能全部解释为标签或领域不匹配。
- 上下文集的两个误报，在 5 秒 r2 和 15 秒 r2 中都发生。延长时限不能解决这些已完成的错误判断。
- 四次超时是检测未完成；没有证据区分连接、服务端等待和生成阶段，不能归因于具体样本难度。
- 执行端口依赖主后端的资源权限、参数校验和事务版本检查。安全模型的 allow 不等于获得数据库授权。

## 从实现能够确认的事实

1. `semantic.py` 已将候选人正文与 trusted_task 分开，但 SecurityContent 只有 source，没有结构化对话角色、当前问题用途或问答绑定字段。前置面试官问题通过 model_output 来源及正文表达。
2. `TrustedTaskContext` 包含允许动作名、公开信息类型和两项交互许可，没有允许资源范围/返回字段。`JsonSemanticReviewer` 有意不传 actor/session/resource ID 和 authorized；让模型猜身份不能替代后端认证。
3. `admission.py` 检查传入的 authorized、动作名、任务动作范围及受众。它不查询业务数据库，也不确认 JSON 参数里的实际资源是否属于当前用户。
4. `execute_checked` 比较刷新前后的完整请求摘要，然后执行 operation。摘要一致不保证数据库在随后提交时仍是相同版本；原有接口文档要求 operation 自行原子校验。

因此下一阶段应把“语义判别能否改善”和“后端是否正确执行权限与事务”分别验证。新增资源/字段校验属于业务权限及参数契约，不是恢复文本关键词攻击分类。

## 本次已完成的执行结果测试

新增 [test_execution_outcomes.py](../../tests/security/test_execution_outcomes.py)，使用真正的隔离 SQLite 写入和查询，并以本地 effects 表模拟发送 outbox；语义检测使用明确的替身。

| 案例 | 数量 | 验证内容 |
|---|---:|---|
| 正常查询、评分、发送 | 3 | 确实产生一次预期副作用，另一候选人的评分不变 |
| unsafe/uncertain/故障/超时/取消 × 评分/发送 | 10 | 回调零调用，数据库和发送记录不变 |
| 错误资源、范围、字段、归属 | 4 | 故意让语义返回 safe，测试后端仍拒绝，未产生披露记录 |
| 候选人冒用评分操作 | 1 | 即使上游自报已授权且模型 safe，测试后端拒绝改分 |
| 重读后版本变化 | 1 | 安全快照一致仍不够，事务中的版本校验拒绝提交 |
| 写入后故障 | 1 | 评分、版本、操作记录全部回滚，回调不重试 |
| 内部内容发送给候选人 | 1 | 来源受众准入直接拒绝，模型和发送器均未调用 |
| 主动绕过端口的负对照 | 1 | 实际产生本地发送记录，证明观察器能发现副作用，也说明未接入的操作无法被端口保护 |

22 项全部通过。超时案例注入 TimeoutError，只验证失败语义，不测真实 API 等待时长。竞态案例确定性模拟提交顺序，不代表并发压力测试。

**这些测试验证接口和测试后端的联调约束，不是 100% 攻击识别率。** 新增权限/字段/事务检查在 Sandbox 中示范，主后端尚未接线；没有真实邮件、HTTP 外传或生产数据修改。攻击文本经业务 Agent 生成工具调用的完整链路仍未测试。
