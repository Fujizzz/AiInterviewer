# 恢复缓存检查预留与重复证据粒度

## 预留最后一次检查

正式面试的轻量出题流程仍共享每轮三次检查上限，缓存可用性和草稿质检都计入其中。首次草稿仍正常检查；一旦本轮已有失败草稿，只剩一次额度且另一个话题存在未用、兼容且可问的开场缓存题，就停止改写，返回 `QUALITY_RESERVED_FOR_RECOVERY`。

控制器收到这个原因后进入恢复切题，优先检查恢复话题的缓存。该次检查也计入原来的三次总上限。缓存合适则直接使用，不合适或请求失败则继续模板兜底，不重置预算、不追加出题模型调用。没有合适恢复缓存时，保留原来的三次草稿检查机会。

失败标记保存在本轮共享预算中，因此 RAG 出题失败后即使进入普通出题，也不能通过新建 ReAct 循环花掉预留额度。该变更没有调整 RAG 的检索算法。独立预生成没有恢复切题流程，不启用此预留。

## 重复判定要求具体证据

默认轻量质检增加 `answer_evidence_kind`：`concrete_answer`、`summary_only`、`offer_only`、`uncertain`。要以“已经回答”为由阻止追问，必须同时满足直接覆盖、确切历史回答引用，以及相对于新问题足够具体的回答证据。

仅列出 shape、dtype、device 等检查项，不代表已说明一条断言的具体实现；“我可以解释检查方法”也不代表已经解释。提示词提供这两类反例及真实具体断言的正例。对于仅包含中英文解释意愿的引用，代码另作轻量检查，避免仅凭模型的 `direct` 标记拒绝追问。有完整具体实现的引用仍可证明重复；简短但足以回答概述问题的清单也仍可证明概述问题重复。

模型输出重复类型却没有确定关系、直接覆盖或具体证据时，该重复项记为警告，不追加复核 API；仍声称有直接具体证据却引用不存在历史记录、或问题引用不合法时，继续按无效质检处理。明确拒答和具体未知详情的重复追问保护保留。
