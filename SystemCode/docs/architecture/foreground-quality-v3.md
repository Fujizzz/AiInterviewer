# 实时决策与后台重规划

本次改动解决目标完成误判、矛盾证据继续评分、实时分析过重及重规划阻塞下一题四个问题。Shadow 管线保持原有行为。

## 实时回答决策

`RealtimeDecisionAdapter` 使用 `CompactAnswerDecision`，一次同步调用只产出回答状态、下一信息缺口、目标覆盖增量、事实关系及局限的片段 ID。原文每次只发送一份；近期同项目回答与已采纳的更早证据按回答 ID 去重。程序根据原始片段还原引用，不要求模型重新输出摘要、引文和能力评分。

能力评分继续走既有后台任务，不参与实时决策等待。调用超时、重试预算和出题质量检查不变；无效片段 ID 仍产生不可用分析，不能证明候选人能力不足或目标完成。

目标完成必须具有当前回答的有效证据，满足该目标的完成标准，并且没有涉及其证据的未解决冲突。一般局限（例如没有线上统计）单独保存为 `analysis.limitations`，进入最终报告；它不能自动成为所有目标的缺口。若目标本来要求线上测量，缺少测量仍应保留为该目标的缺口。当前问题回答完整不等于整个目标完成。

## 事实关系与评分

模型分别输出关系类型及两条事实是否兼容。将不兼容或未确定的关系标为 `clarifies` 时，程序转换为 `disputes`；只有明确更正才应使用 `supersedes`。上下文区别必须引用当前回答原始片段，不能虚构版本。

所有关系仍核验同项目的真实历史回答、当前原文及引用 ID。争议同时冻结新旧冲突证据；更正淘汰旧证据；无关证据保留。实时反馈与迟到的后台评分都应用持久化关系账本，再重建分数，因此迟到的评分不能复活已淘汰或有争议的证据。语义兼容性仍依赖模型判断，程序约束不能保证识别所有矛盾。

## 后台重规划与提交

CLI 和后端会话启用 `background_replanning=True`。初始计划仍同步建立；后续重规划在旧计划可执行时不等待模型。旧分配耗尽或时间漂移时先使用本地预算编译保持计划可执行，再在正常回合提交成功后启动 Planner。

每场面试最多一个后台提案任务，输入是已提交状态的深拷贝。任务只生成目标偏好，不生成问题，不写仓库。下一正常回合消费已完成提案，根据最新剩余时间、目标覆盖和拒答状态重新编译，随后通过原有 CAS 提交。以下提案作废：基础计划版本失效、目标版本变化、收到新反馈后仍试图替换目标。

提案在 CAS 成功前保留，重算不会重复请求 Planner。完成或拒答目标不会被恢复，当前问题的关联由正常执行器维护。服务关闭时取消并回收任务。

`pending_replan_trigger` 随 JSON 会话状态保存，不需要新增数据库迁移；模型提案本身只驻留进程内。进程重启后可根据待处理意图重新规划，不能将此机制视为持久化任务队列。底层服务默认保留同步模式兼容旧调用方，生产入口明确启用后台模式。

## 验证边界

相关测试覆盖引用校验、目标独立覆盖、争议双方冻结、迟到评分、慢 Planner、拒答目标过滤、过期提案、CAS 重算及关闭取消。真实 API 回放验证了历史取舍回答能够完成目标，ROI 冲突被识别为争议，并观察到下一题先于后台 Planner 完成返回。

真实回放不是新一场完整 15 分钟面试。一次后续回合仍触发已有的质量修复耗尽结束行为，需要单独评估；进一步续跑被供应商 `400 Arrearage` 阻断，不能声明全部场景通过。

## qwen3-max 续测发现的前提误拦截

后续完整面试暴露：简历已经写了使用 FFmpeg 流式管道，但审查器将“实现细节尚未回答”误判成“无依据经历”。`GroundingCheck` 因此增加 `premise_basis` 和 `asserted_fact_quote`。确认无依据前提必须指出一个新的事实断言，不能用 how/如何请求或来源中已有事实作为证据；缺少证明的审查仍作为冲突处理，不能自动放行。

真实 API 精确回放清除了两份原始 FFmpeg 题稿的误判，仍拦截虚构 Kafka 实现。重新运行 15 分钟配置面试后正常退出，面试实际计时 881 秒、剩余 19 秒不足新问题。完整记录见 [续测报告](../../output/live_manual_15min_20261009T141744Z/report.md)。这次没有改变修复预算或整场终止策略。
