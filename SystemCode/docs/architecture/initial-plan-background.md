# 自我介绍期间后台初始规划

固定自我介绍提交成功后，服务立即创建后台初始规划任务。模型读取已有简历结构、话题和预算，任务只操作独立快照，不自行发布正式状态。此任务与后续动态重规划分开管理，也不依赖 RAG 预热完成。

提交自我介绍时，已完成且有效的模型计划会按当前剩余时间重新编译，在首道技术题的事务中一起提交。尚未完成、失败或连接恢复后丢失任务时，服务直接使用本地初始规划，不再同步调用模型。首道技术题仍使用现有缓存优先及必要的可用性检查流程，因此并不保证回答提交后零等待。

用户结束面试、首次技术题成功提交及连接关闭时会取消或清理初始任务；晚到结果不会覆盖正式计划。状态冲突重算可以复用同一份已完成提案，不会重复调用规划模型。自我介绍继续按未评分回答保存，不进入能力证据。

回归覆盖后台结果就绪、未就绪、失败、任务丢失、事务冲突、重复提交、开场结束和禁用规划。真实 API 冒烟脚本为 `backend/tests/run_initial_plan_smoke.py`，输入此前测试的 `result.json`，复用其中的简历结构和缓存题目；模拟三十秒自我介绍，只推进至首道技术题，不测试完整面试、评分或 RAG。

真实补测另发现模型经常返回超过 300 字符的 `reason`，触发供应商适配器的结构修复重试，仍超长后整份规划降级。该说明字段现于本地截断至 300 字符，保持存储边界；话题、目标、版本等业务约束照常校验。
