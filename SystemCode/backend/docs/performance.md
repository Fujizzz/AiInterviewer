# 面试等待优化与协作事项

本轮修改范围为 backend。目标是减少点击开始后的重复解析等待、提前交付已有结果，并让等待可解释。
没有把评价与正式出题并行，没有更改 Agent/评价契约、模型、温度、逻辑预算、阈值或重试。

## 已实现

- 固定自我介绍开场：网页与 CLI 第一题始终为固定文本，不调用出题模型、质检或检索。
  回答以 `unscored_reason=self_introduction` 保存，直接进入项目规划/问答；不调用评估、不进入
  能力证据、不计入未评分或评分失败数量，也不占项目/话题题量。总问题上限在原技术题数外增加 1。
  自我介绍开始即计入实际面试时长；项目规划和后续生成的等待仍计时。
- 简历结构按版本持久化：文字上传、PDF 提取完成、保存编辑版时调用原有解析器并保存完整 CandidateProfile。
  面试页使用 `can_interview=true` 的版本 UUID 直接 start，同版本跨连接、跨面试读取结构，不重复解析。
  等待前移到上传/保存阶段；新编辑版独立解析，失败或旧版本在个人中心显式准备资料。
  原始文本客户端的 prepare 仍只在同连接精确匹配文本时复用。详见[版本接口](resume-versions.md)。
- 实际阶段事件与计时：前端显示真实阶段、请求总等待和阶段耗时。计时器不参与策略或超时。
- 评分先行：最后一轮先交付已提交状态的数值结果，再生成报告文字。使用同一个报告聚合函数，
  不引入另一套评分公式，不增加模型调用。
- 诊断日志：每个阶段与模型调用的耗时、生成修复原因以及 Agent 返回的生成方式均可追踪；
  不记录简历、回答、问题正文、密钥或完整供应商异常。
- 前端取消、断线、清空和旧事件隔离：停止显示计时，保留版本选择；报告不完整时保留数值并明确说明。
- 保留旧客户端：只对明确订阅 progress_events 的请求交付扩展事件，原有请求序列保持兼容。

真实长测发现较大模型的安全审查可能超过原 5 秒上限。后端支持
`AI_SECURITY_SEMANTIC_TIMEOUT_SECONDS`（默认 5，范围 0–120 秒且不含 0）；本地 `.env` 配为 30 秒。
这是当时启用审查的测试配置；`run_live_intro_rag.py` 现在固定关闭安全审查。
启用审查的部署仍会在超时或拒绝时阻断输出。
长对话的完整审查请求还会包含历史和计划诊断，本地 `AI_SECURITY_MAX_SCAN_CHARS` 调为 500000；
默认仍为 100000，超限仍拒绝。项目知识检索使用技术名加短话题，避免长简历声明拖慢 CPU 查询向量化。

## Agent / App / Evaluation 团队需要配合

| 事项 | 当前约束 | 建议交付与验收 |
| --- | --- | --- |
| 原生异步模型适配器 | Agent LLMPort 是异步，但 App 的 StructuredLLM、简历解析、评价和报告使用同步调用并在线程中执行 | 统一异步协议与客户端生命周期；覆盖超时、取消、重复请求和参数保持；不复制供应商代码到后端形成第二套逻辑 |
| 中文问题校验 | QuestionValidator 用空格分词，中文可能触发 TOO_SHORT | 根据本轮日志确认，再由 Agent 团队定义多语言长度规则与样例；不可直接放宽阈值掩盖失败 |
| 即时评价与详细反馈拆分 | coverage、confidence、difficulty 等反馈直接影响下一题；当前评价输出已较精简 | 明确最小必需反馈及延后字段，验证决策/评分一致性及实际耗时收益 |
| 动态追问 | 追问依赖最新回答和当前缺失信息，不能用固定首问替代 | 保留现有生成与完整质检；缓存只优化新 topic 首问和准备好的项目原理题 |
| 统一报告状态契约 | 后端已观察模型异常并提供 report_narrative_status；终端共享函数未提供状态 | 后续由共享报告接口统一成功/失败标记，覆盖所有调用入口，避免各适配器分别观察 |
| 供应商调用指标 | 同步适配器返回模型结构体，未暴露 token、首字耗时及 SDK 内部重试次数 | 提供不含正文的结构化调用观测接口，关联请求/调用 ID，保留原参数和失败行为 |
| RAG 资料准备 | 已接入 PostgreSQL/BGE；本机资料覆盖有限 | 准备阶段保存问题及引用；无可用证据时记录 unavailable，不伪造成功 |

## 衡量收益

分别记录首次点击到问题、预解析耗时、回答评价耗时、下一动作耗时、最后回答到数值评分和完整报告耗时。
比较同一模型、输入、题数和策略下的中位数及高分位，额外记录模型调用数量与修复原因。
离线测试只证明缓存减少一次解析调用、评分事件先于阻塞的报告阶段；不代表真实模型提速百分比。

上传阶段解析复用已进行真实模型冒烟验证：合成简历上传解析入库 7.664 秒，同版本两场面试均返回首题，
面试阶段 ResumeExtraction 调用次数为 0。首题仍包含规划、生成、质检耗时，这不是整体提速比例基准。
复现命令：在仓库根运行 `.venv/Scripts/python backend/tests/run_resume_profile_smoke.py`（会调用已配置的真实模型）。
报告见 `output/resume_profile_live_smoke/report.md`。该冒烟使用隔离 SQLite，不覆盖真实 PDF 沙箱、
WebSocket 安全审查或 RAG；它们分别由已有流程与离线集成测试验证。
