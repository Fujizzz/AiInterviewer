# 回答结束意图粗筛：数据调查与训练方案

调查日期：2026-10-03。目标为服务器上的本地二分类模型，先过滤转写片段，
只有候选片段进入现有 Qwen Flash 确认器。用户明确选择保留 Qwen 确认；
本地分类结果不得直接触发 MCP 或结束回答。现有三秒静默、补充撤销和最终凭据流程不变。

## 标签边界

- `1`：用户正在表达结束自己对当前面试问题的回答，可以提交给 Qwen 再确认。
- `0`：普通回答内容、项目成果总结、仍要继续、否定、引用他人的结束话语、单独道谢。

这与“完整句子 / 不完整句子”的标签不同。粗筛的误报可交由 Qwen 再判断，
但漏报会阻断结束检测，因此验证必须重点记录正类召回率，而不能只报告总体准确率。

## 实现与固定条件

选择 [paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2)
第一轮作为冻结的多语编码器，再训练一个二分类头；第二轮微调编码器。官方模型卡说明它支持 50 种语言，
输出 384 维向量；此次 Hub 元数据查询的参数总数为 117,654,272。
它比字符 n-gram 分类器占用更多资源，但能利用预训练语义表示；是否满足服务器延迟要求
仍须实测，不能把模型名中的 Mini 当成性能保证。

固定候选基础版本：`e8f8c211226b894fcb81acc59f3b34ba3efd5f42`。
该版本提供 ONNX 和 INT8 导出。最终选择哪个导出，须记录运行设备、结果差异和实际耗时。
训练和服务器推理采用一致的文本尾部、分词截断与池化处理，避免丢掉最新结束表达。

用户于 2026-10-03 授权专用合成数据集。训练前固定并记录：

1. 数据来源、生成与标注方法、人工检查范围、样例 ID 和标签定义；仅使用虚构内容。
2. 按生成来源场景分组的训练/验证/测试划分，同一组的变体不跨集合。主题和措辞仍可能
   在不同生成组间重复，不能据此声称所有近似表达都独立或验证了未见主题泛化。
3. 模型版本、训练参数、随机种子和依赖版本；阈值只在验证集选择。
4. 中英分别报告正类召回率、误报率、混淆矩阵、送入 Qwen 的比例，以及 CPU 延迟。
5. 测试集只做最终评估；合成集效果单独报告，不据此声称真实面试准确率。

Kaggle 使用私有数据集和私有训练 Notebook，导出模型、阈值、分词器及训练报告。
服务器启动时显式加载配置的模型；加载或推理失败应报错，不恢复关键词规则，
也不静默绕过粗筛。Qwen 仍独立完成最终结束意图确认。

## 已发现的评估一致性问题

检查训练/推理的数据流时发现：训练与评测一次编码 16 条，业务一次编码 1 条。
虽然两端复用同一个特征处理函数，动态量化编码器的分数会随批量形态变化。
同一台 CPU、同一产物、同一对照集的批量/单条分数最大相差 `0.061826`，
3 条对照样例跨过上述阈值。证据见[一致性检查](../../training/answer_completion/results/v1/batch-consistency.json)。
本机单条探测与 Kaggle 批量评测不能当作完全一致的分类结果；上述正式报告保留原实验条件。

此外，原合成类别中 152/160 个拟间接结束、154/160 个拟移交话轮被实际语义盲标判为负类，
多为项目结果总结或询问面试官想听哪些进一步细节。修正标签是必要的，但正类自然表达覆盖
仍不足。不能通过恢复这些错误标签提高看起来的指标。

用户已明确批准“同意补充数据并微调编码器”。第二轮使用独立配置
[`experiment-v2.json`](../../training/answer_completion/experiment-v2.json)，保留第一轮结果。
补充 1,600 条语义对照样例，盲标后与第一轮的 1,200 条**训练行**组合；第一轮验证/测试
不进入训练。新验证/测试仍按新的来源组预分配，中英每种语言各 60/10/10 组。
另写的 [`challenge-v2.jsonl`](../../training/answer_completion/challenge-v2.jsonl) 有 80 条
新语义对照；第一轮对照仅作已知回归，不参与第二轮验收。

第二轮微调全部编码器参数及线性二分类头，固定种子 42、5 轮、批量 16，编码器/分类头
学习率分别为 2e-5/0.01。按验证集加权 BCE 最低轮选择模型，导出 INT8 ONNX 后，所有
阈值选择、正式评估和服务器推理均使用单条输入。验收召回率和负类拦截条件保持不变。
生成的短直接结束语及完全重复文本显式拼接同场景已有回答细节，保持原意、标签和划分；
原始输出与每条绑定 SHA256 的[改写记录](../../training/answer_completion/data-v2-corrections.json)
保留。此操作属于离线合成数据准备，不是线上关键词筛选或按词语打标签。

新增数据经盲标后正类 602、负类 998，共修正 198 条生成类别与实际文字不一致的标签。
组合训练集为正类 699、负类 1,701；新验证集正类 73、负类 127，新测试集正类 76、负类 124。

## 服务器两层验证与提示修订

在 Ubuntu 22.04 / Python 3.12.14 隔离发布环境执行真实粗筛和 Qwen Flash，保持既有
3 秒总期限和零重试。最初 80 条检查无超时/误报，但有 3 个漏判：1 个本地粗筛漏判，
2 个是 Qwen 将“项目仍在进行，但本人回答已结束”判为未结束。
针对项目/回答的指代关系修订提示后，两项问题消失，但一次双重否定产生误报。
最后增加后文继续解释优先和双重否定的语义约束，未加入本地关键词匹配。
各版提示和检查结果在 [`results/v2`](../../training/answer_completion/results/v2) 保留。

最终 80 条**已知回归**中，结束召回 39/40（97.5%），非结束拒绝 40/40，零供应商错误；
剩余一个漏判来自未改动的粗筛模型。另写的项目进度/回答意图 12 条、否定 8 条冒烟
共 20 条全部符合标签，无超时。模型权重、验证阈值、三秒静默和 API 期限均未改变。
服务器 CPU 粗筛 P95 约 10.93ms；已知回归中真实 Qwen 候选调用 P95 476.10ms。
