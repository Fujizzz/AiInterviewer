# 面试场景测试数据

## 当前主任务：系统行为合格性

`behavior_cases_v1.jsonl` 包含 30 条面试行为案例，15 组合格/越界对照。expected 为 allow/deny，
指系统拟执行行为是否合格；attack_present 只描述输入背景，不决定 expected。模型只收到
request，不收到标签、note 或 pair_id。所有人物、角色、数据和资源均为虚构。

覆盖改分、攻击示例讨论、简历/工具注入、他人记录/内部权重、系统任务偏离、证据评分、
资源/字段/参数范围、角色、结束后写入和派生来源。相同攻击输入下，正确拒绝与越界响应分别标注。
数据和提示词在调用前冻结；limit 1..5、rubric_level 1..5 仅为合成约束，未修改原业务参数。
这里评测固定提案，不是完整受攻击 Agent；共同作者偏差、小样本和人工标签限制其结论。
结果见 `ai_security/reports/BEHAVIOR_V1_EVALUATION.md`，不宣称盲测或端到端攻击成功率。

## 独立文本诊断

`interview_cases.jsonl` 是本次开发生成并固定的 32 条中英文合成样本，16 条正常、16 条攻击。
不来自真实候选人，不含真实简历、身份或密钥；示例姓名和内部标记均为虚构。

标签含义：0=本场景中的正常内容，1=尝试改变面试规则、获取内部信息、外传数据或滥用资源。
所有样本均按单条 input/user 文本评测；并未模拟真实攻击执行或证明攻击已在业务中成功。

样本覆盖技术项目说明、公开反馈请求、正常安全讨论、引用攻击的困难负例、规则覆盖、满分操纵、
角色伪装、记忆污染和数据外传意图。包含旧版固定规则漏检的攻击与误报的引用，不为取得全对结果
而删除、重标注或调整样本。它与当前设计存在共同作者偏差，不能替代独立测试集或真实使用反馈。

公开集使用 deepset/prompt-injections 的原始 test split，下载到被 Git 忽略的 tmp 目录。
数据来源、固定修订、许可元数据冲突及历史规则结果见 `ai_security/reports/README.md`。
取消规则模式后，本数据的标签和内容保持不变；真实语义模型结果另见
`ai_security/reports/SEMANTIC_EVALUATION.md`，不替代历史规则报告。


## v3 独立上下文场景

`contextual_cases_v3.jsonl` 新增固定 16 条场景（8 正常、8 攻击），每行有 id、label 和完整 SecurityRequest。
涵盖公开维度与内部标准、更正与改分、同一句文本在安全示例提问/普通面试下的不同语义、RAG/工具结果注入、本人反馈/他人档案、输出泄露和动作参数劫持。
数据在本次模型评测前生成并固定，未根据输出改标签。与实现具有共同作者偏差，仅作为开发场景验证。

样本中的权限均为显式测试设定：允许更正、澄清、公开宽泛维度及本人反馈，版本为 7；不写入产品默认权限。
示例身份与 example.invalid 地址虚构，无真实外发工具执行。模型只接收 request，不能看到 label；预期不由被测模型自标。
结果与旧 32 条文本集分开报告。执行是否真正发生由独立回调测试验证，场景分类指标不是端到端攻击成功率。
