# 文字面试输入输出接入验证

日期：2026-09-26。范围：`/ws/agent/` 输入绑定、业务输出审查、获准结果保存及历史公开。工具执行与内部评分提交未接入，不修改旧评测样本、标签、推理参数或基准报告。

## 实现

- `InterviewIOGateway.bind_input` 在业务模型调用前检查归属、当前请求/问题及状态，区分简历、岗位和回答来源。
- `publish` 检查完整资料预览、问题（含附带评价）、先行评分及最终报告；只在检查通过、重读一致后调用保存/发送端口。
- 最终保存事务复核归属、版本及请求状态。历史接口只读有完整校验记录的响应，不从原始内部问题/评价/上下文回填模型正文。
- 检查拒绝、异常、不确定、超时及覆盖不全均停止本次会话；取消不继续发布，无自动重试或失败放行。
- 安全模型仍采用项目配置，语义预算 5 秒、完整请求预算 100000 字符。新增安全决策日志只记录 ID、结论、有限违反项、异常类型与耗时。

## 真实安全模型小规模连通检查

详见 [原始元数据](interview-io-live-smoke.json)。通过真实 ASGI、隔离测试数据库和项目的真实 qwen-plus 安全 API，业务生成采用虚构资料及 `FixtureLLM`，分别执行一次 prepare 和一次 start。

- 两次安全模型调用均收到响应，分别产生 `prepared`、`question`，请求均保存为 succeeded。
- 保持 temperature=0、enable_thinking=false、SDK 重试为 0；网关仍为 5 秒，没有借用 15 秒实验策略。
- 未测试真实业务模型的完整面试，也没有以该两例估计误拒率、漏放率、延迟分布或并发容量。
- 先行评分与最终报告在实际协议/数据库上用可控安全替身验证；本次未对这两个出口做真实安全模型调用。

## 使用限制与主开发配合

1. 内部评分及状态可能在输出审查前已提交；输出拒绝不能回滚这些副作用。
2. 原完整输出中的计划、权重和诊断字段同样接受保密审查，可能导致整包拒绝。下一步应与主开发团队明确候选人可见字段，不能用删测试字段、放宽要求或延长时限来伪造提升。
3. 旧无校验记录的数据仍保留在库中，但不再经历史接口公开模型正文。资料、状态或评价缺少已检版本时返回 null；`security_output_available` 指示是否存在获准响应。
4. 保存与网络发送不属于同一事务；已保存的获准结果可能未送达。先行评分成功发送不保证后续文字报告也获准。
5. SHA256 校验记录依赖受信任的后端写入，不是签名或可交给客户端复用的授权令牌。
