# 安全引擎 v3：任务上下文、执行边界与独立评测

日期：2026-09-26。范围按用户确认：升级安全模块和联调接口，网页主流程不默认启用。没有恢复关键词/正则攻击分类，没有引入模型重试、失败放行或备用模型。

## 已落地的边界

- 后端显式提供任务权限、公开信息范围与状态版本；原文中的角色或权限声明不能覆盖这些结构化字段。
- 内容附带来源、允许受众与派生关系；程序按父来源受众交集限制传播。这是快照级数据权限约束，不是完整 CaMeL 解释器或自动脱敏。
- 语义模型按任务判断指令覆盖、目标劫持和泄露，返回有限原因码与证据引用，不拥有业务工具。
- `build_interview_request` 适配已有 InterviewState；`execute_checked` 检查后重读完整快照，拒绝过期决策，再调用一次业务操作。
- 提交时的原子状态/授权校验仍由主开发侧承担；库级回调测试不能证明真实数据库或 WebSocket 已受保护。

设计参考及限制见 [公开实现调研](../../docs/modules/AI_SECURITY_DESIGN_REVIEW.md)，实际接口见 [联调约定](../../docs/modules/AI_SECURITY_INTEGRATION.md)。

## 实验条件及版本

复用 backend/.env 的 DashScope/qwen-plus，温度 0、enable_thinking=False、SDK 超时 30 秒、外层安全时限 5 秒、SDK 重试 0。每条样本顺序调用一次，未改变这些参数或客户端生命周期。

原 32 条面试文本与 116 条 deepset 官方 test 的修订、原序、标签和校验和保持不变。新增 16 条完整上下文场景（8 正常、8 攻击）独立报告，标签在运行前固定，模型只能接收请求，不能看到标签。

本次改变了安全契约、任务上下文与检测提示词。v3 明确允许更正、澄清、公开宽泛评分维度及本人反馈；这些仅是测试场景设置，不自动成为产品默认权限。因此 v2/v3 是整套方案的对照，不是只更换模型的严格消融实验。

初始 v3 增加任务对齐和来源判断；修订 r2 进一步说明合法的重复/翻译题目，以及在面试题要求下引用安全攻击示例。这次修订依据开发样本误报作出。全部结果保留，不能把这些已看过的样本称为盲测，也不能把提示词修订前后的结果合并成一次实验。

初始与 r2 提示词分别保存在 [初始提示](prompts/task-context-v3-initial.txt) 和 [r2 提示](prompts/task-context-v3-r2.txt)，UTF-8/LF 内容摘要与各轮 metadata 对应。JSON 中记录实验开始时的源码摘要，包含注释；后续注释澄清和 CLI 非法输入错误脱敏不改变有效样本的检测、模型参数和计分逻辑。

## 计分解释

召回率分母包含全部攻击；误报率分母包含全部正常样本；未完成检查单列，既不算识别成功，也不被删除。程序准入拒绝单列 admission_denied，本次真实模型各批次均为 0。

正常请求未放行比例包括正常样本上的误报与检查失败，和误报率一起反映可用性。模型分类通过不等于真实任务成功或攻击执行被阻断；真实业务流程尚未接入。

## 诊断与实际限制

1. 原 32 条面试样本中，初始 v3 误拒了翻译题目的正常请求；r2 中这条恢复放行，但仍出现超时。不能因没有明确漏判就声称 100% 召回。
2. 新 16 条上下文场景中，r2 识别全部 8 条攻击，但仍误拒“按题目要求举攻击示例”和“查询本人记录”，另有一次正常输出检查超时。补充提示词并没有稳定解决引用语境与已授权正常操作的判断。
3. 当前任务上下文比孤立文本更明确，但尚无细粒度的、经后端确认的当前问答目的和动作数据范围映射。仅靠通用 LLM 猜测这些边界仍可能过度拒绝；数据来源标签也不是语义安全证明。
4. 已完成批次中的超时对应适配器取消记录；未发现 HTTP 报错或契约解析异常。这个证据不能单独区分客户端连接、服务端排队及生成耗时，更不能证明延迟变化由提示词引起。未延长既有时限来改善分数。
5. deepset 缺少原始任务和多轮轨迹；仍保持原标签计分。部分场景不匹配不能解释掉全部漏检，结果不等于面试产品的真实攻击成功率。
6. 本次模型别名未锁定服务端权重，调用时段与负载未受控；生成温度为 0 也不能保证重现完全相同输出。合成场景存在共同作者偏差。

接口具备联调所需的拒绝和失败传播边界；语义误报、漏检与 5 秒内可用性仍未达到可默认上线的证据要求。
