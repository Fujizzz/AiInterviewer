# 项目覆盖与证据校验收尾

规划以每个简历 project 至少问一道技术题为优先约束，深挖仍由模型决定，但不能用新增深挖替换未访问项目。

## 项目覆盖

- `planning/projects.py` 根据已提交问题、持久化 thread 和访问计数判断项目是否访问过。自我介绍、生成草稿、规划中的选择不算已经提问。
- 本地编译为每个未访问项目补回至少一个合法 topic，保留已有目标与证据；没有合法 topic 时记录 `project_coverage_unavailable`。
- 预算分配先为未访问项目各保留一个题数槽位和一轮时间，再分配可选目标。必要时释放可选的收尾及缓冲时间。
- 当剩余可用时间不超过“未访问项目数加一”轮，或剩余题数只够未访问项目时，暂停当前项目额外深挖，优先推进尚未访问项目。
- 执行选题、追问准入、问题提交、失败恢复均遵守该规则；原有项目连续访问和显式授权返回规则继续生效。
- 这是有限时长与题数约束下的优先保证。用户主动结束、回答超出剩余总时间、项目没有合法话题等情形不能制造已覆盖记录；不足原因必须留痕。

## 实时分析

`CompactAnswerDecision.limits` 明确要求当前回答片段 ID。适配器逐条验证，错误引用仅记录 `INVALID_LIMITATION_SEGMENT_OMITTED`，不使其他有效分析全部失效。保留合法限制证据、本地能确认的边界及明确拒答状态；存在非法限制引用时不宣告 thread 完成，不把模型说明文字转换成候选人原话。

## 质检与缓存

质检继续要求最短且不超过 500 字符的重复证据，但兼容模型违反长度要求的返回：超长引用对应的重复结论降为警告，其他独立结论继续生效，不盲目截断引用，不增加模型重试。

缓存准入增加来源 ID、精确回答引用、覆盖程度与证据类型。只有来源可定位、原文能匹配、直接覆盖且属于具体回答时，才采纳 `REPEAT/COVERED` 拒绝。概述、关键词和“可以解释”的承诺不足以拒题。原有已使用缓存 ID、题目原文重复、话题覆盖、不可用细节和目标匹配检查保留。

不迁移数据库、不重新解析简历、不重新预生成问题；此前使用的兼容缓存版本仍可复用。
